## 2. 칸 재지정 — 시작 `suffix | bit`, 간격 `2^(d+1)` (게이트 Q1 2/2 fail → 설명 후 통과)

`src/index/paged_hash.rs:138-147`

```rust
let suffix = (mix(key) & (bit - 1)) as usize;                         // 원래 끝 d비트
let (len, step) = (1usize << self.global_depth, 1usize << (d + 1));   // 끝 d+1비트를 지키는 간격
let mut s = suffix | bit as usize;                                    // 끝 d+1비트 = suffix|bit 인 첫 칸
while s < len {
    ...
        dir.slots[s % DIR_SLOTS] = new_id;   // 시작 칸부터 쓴다
        s += step;
    ...
}
```

### 2진수 기초

| 표기 | 뜻 | 예 |
|---|---|---|
| 자리값 | 오른쪽부터 1, 2, 4, 8, 16… | `1000` = 8, `0101` = 5 |
| `1 << n` | n번 자리에만 1 | `1 << 2` = `0100` = 4, `1 << 3` = `1000` = 8 |
| `a \| b` | 자리마다 둘 중 하나라도 1이면 1 | `0001 \| 0100` = `0101` = 5 |

### 규칙: 버킷 = "끝 몇 비트가 같은 칸들"

- 지역 깊이 d인 버킷은 끝 **d비트**가 `suffix`인 칸 전부 → `suffix`부터 `2^d` 간격, `2^(전역 − d)`개.
- 분할 = 보는 비트가 d+1개로 늘어남. 새 버킷 = 끝 **d+1비트**가 `suffix | bit`인 칸.
  - 시작 = 그런 칸 중 가장 작은 것 = `suffix | bit`.
  - 간격 = `2^(d+1)` — 더해도 끝 d+1비트가 안 바뀌는 최소 단위.
- 10진수 비유: 끝 두 자리가 37인 수 = 37부터 100 간격.

| 예 | 분할 전 칸 | 새 버킷 칸 |
|---|---|---|
| 전역 3, d=1, suffix=1 | 1, 3, 5, 7 | 3, 7 (s=3, step=4) |
| 전역 4, d=2, suffix=1 | 1, 5, 9, 13 | 5, 13 (s=5, step=8) |

| 틀린 코드 | 써지는 칸 (전역 3, d=1) | 문제 |
|---|---|---|
| 시작 = `suffix` | 1, 5 | 남아야 할 칸을 옮긴다 — 정반대 |
| 간격 = `2^d` | 3, 5, 7 | 끝 1비트만 지켜 남아야 할 5가 섞인다 |

이 분할은 d < 전역이면 **디렉터리를 두 배로 하지 않는다**(칸 수 그대로, 화살표만 바꾼다). 두 배는 `d == global_depth`일 때만.

### 오답 노트

| 내 답 | 실제 |
|---|---|
| "앞에 1이 붙어 4자리(1000)가 된다" | 그건 디렉터리 **두 배**. d(1) < 전역(3)이면 `double()` 안 불림 — 기존 칸의 화살표만 바꾼다 |
| 반례 계산 "5, 9" / "5, 7" | 루프는 **시작 칸에 먼저 쓰고** 더한다 → 1, 5 / 3, 5, 7. 9는 `s < 8` 실패 |
| "1001이 s, 1111이 step" | `1 << n`은 1이 하나뿐. `bit = 0100`, `s = 0001 \| 0100 = 0101 = 5`, `step = 1000 = 8` |
| "1000 = 16" | 자리값 8·4·2·1 → 8 |

## 3. 지역 깊이를 올리지 않으면 — 무한 분할 (게이트 Q2 pass)

`src/index/paged_hash.rs:101-115` 요지

```rust
let d = { /* 버킷의 local_depth */ };
if d == self.global_depth { self.double()?; }   // global_depth += 1
let bit = 1u64 << d;
...
    old.local_depth = (d + 1) as u64;           // ← 이 줄을 지우는 변이
```

계측(eprintln) 결과: `SPLIT d=0 g=0` → `DOUBLE` **1번** → `SPLIT d=0 g=1` 약 20만 번(10초, 끝나지 않음).

1. 두 배 뒤 전역 = 1, 옛 버킷 d는 0 그대로 → `0 == 1` 거짓 → 다시 두 배 안 됨.
2. `bit = 1 << 0 = 1` — 첫 분할과 **같은 비트**.
3. 첫 분할에서 bit 1인 키는 이미 새 버킷으로 나갔다 → 남은 키는 전부 bit 0 → 두 번째 분할에서 **전부 제자리**, 새 버킷은 빈 채 할당. 옛 버킷은 여전히 넘침 → `insert`의 `count <= bucket_cap`이 영영 참이 안 되어 `split` 반복(매번 `new_page`로 빈 버킷 누적).

(처음 이 변이를 "매 분할마다 두 배 반복"으로 잘못 기록·출제했다가 계측으로 정정했다.)
